### 1.1 Пользовательский опыт

1. **«Поделиться результатом» — карточка-картинка.** Кнопка на `/results`
   генерирует PNG 1080×1350 (4:5) и отдаёт его системному шарингу. Бэкенд
   не нужен. Дизайн утверждён:
   - в цветах приложения и текущей темы (light/dark), шрифт Inter;
   - шапка: логотип, дата; пилюли режим · сложность · категория;
   - крупный счёт; ниже — сетка ответов в стиле Wordle (верно/ошибка) для
     Классики, На время и Блица; для Выживания вместо сетки — число
     пройденных вопросов и оставшиеся жизни;
   - плитки «Верно», «Серия» (иконка пламени), «Уровень»; бейдж «Новый
     рекорд», если он есть; внизу — домен и призыв «побьёшь?».

   Реализация:
   - **Отрисовка — вручную на Canvas 2D**, не `html-to-image`/
     `modern-screenshot` (проблемы со шрифтами, CSS-переменными и
     Safari). Чистая функция `renderShareCard(summary, theme, t) → Blob`;
     перед рисованием `document.fonts.load('500 48px "Inter Variable"')`,
     иконки lucide — через `Path2D`; числа — через `Intl.NumberFormat`,
     строки — через i18n (en/ru).
   - **Цепочка отправки:** `navigator.canShare({ files })` →
     `navigator.share({ files, text })`; иначе PNG в буфер через
     `ClipboardItem`; иначе скачать PNG и скопировать текстовую строку
     («Блиц · Hard · 9/10 · 1 240 очков»).
   - **Ловушка Safari:** `share()` должен вызываться в пределах user
     activation, поэтому PNG генерируется заранее при mount экрана
     результатов, а клик сразу вызывает `share()` с готовым файлом.
   - **Тесты:** unit — выбор ветки цепочки отправки и раскладка карточки
     по режимам; e2e — ветка со скачиванием (в Playwright нет
     `navigator.share`).
   - **Вне объёма:** превью ссылки в мессенджерах (OG-картинка) рендерится
     только сервером — при необходимости позже через `@vercel/og` на
     прокси.
2. **Сессия переживает перезагрузку + защита от случайного ухода.**
   `useQuizSessionStore` (`src/shared/lib/session-store.ts`) не
   персистится: F5, закрытие вкладки или выгрузка вкладки мобильным
   браузером посреди квиза теряют весь прогресс (и `/results` после
   reload пуст).
   - `persist` в `sessionStorage` (вкладочная жизнь, не засоряет
     localStorage), со схемой Zod и версией, как у остальных сторов.
   - При возврате на `/` или `/setup` с незавершённой сессией —
     «Продолжить квиз?» (продолжить / начать заново).
   - Уход с `/quiz` во время игры — подтверждение через `useBlocker`
     TanStack Router и `beforeunload` для закрытия вкладки.
   - **Решение не принято — таймеры после восстановления:** «На время»
     и Блиц продолжают с сохранённого `timeRemaining` (время вне
     вкладки не считается) или вычитают прошедшее. Локально
     античит не важен, проще первое.
3. **Полный разбор ответов на `/results`.** Сейчас показываются только
   ошибки (`result.mistakes`). Нужен разбор всех вопросов: текст,
   ответ игрока, правильный ответ, `explanation`; фильтр «все / только
   ошибки» (по умолчанию — ошибки, если они есть). Данные уже есть в
   сессии (`questions` + `answers`).
4. **PWA: установка на телефон и офлайн-оболочка.** Сейчас в `public/`
   только `favicon.svg`, манифеста и service worker нет.
   - `vite-plugin-pwa` (Workbox): manifest, иконки 192/512 + maskable,
     `apple-touch-icon`; precache оболочки приложения.
   - `/api/*` не кэшировать (NetworkOnly) — свежесть вопросов и
     ошибки провайдеров должны идти как сейчас; без сети live-провайдер
     даёт `network`, как и сейчас.
   - Обновление — `registerType: 'prompt'`: тост «доступна новая
     версия → обновить», а не тихая подмена посреди квиза.
   - `theme-color` уже переключается скриптом в `index.html` — манифест
     должен с ним совпадать.
   - Связано с п. 6: тела вопросов в IndexedDB дают офлайн-режим
     работы над ошибками.
5. **Мета-теги и заголовки страниц.** В `index.html` только
   `<title>QuizApp</title>`.
   - `description`, Open Graph (`og:title`, `og:description`,
     `og:image` 1200×630 — статичная картинка), `twitter:card`.
     Краулеры не исполняют JS SPA, поэтому OG-теги статичны в
     `index.html` и на одном языке (en).
   - `document.title` по маршруту и языку («Результаты · QuizApp»),
     через i18n; `<html lang>` уже обновляется в `src/app/i18n.ts`.

### 1.2 Данные и надёжность

6. **История вопросов: без повторов и «вопрос с ошибкой».** Сейчас
   повторы идут от источников: mock перемешивает детерминированно
   (`src/shared/api/mock-questions.ts`, seed = сложность + категория —
   всегда один порядок); QuizAPI получает `random=true`, но при
   повторах надо проверить, работает ли он вместе с `offset`; trivia
   игнорирует `offset` и отдаёт случайные вопросы.

   - **История ответов** — запись `providerId:questionId →
     { status: correct | wrong | reported, lastSeen }` (id уникальны
     только внутри провайдера). Кнопка «вопрос с ошибкой» на `/quiz`
     ставит `reported`; отправка жалоб на сервер — позже, вместе с
     аккаунтами.
   - **Приоритеты, а не запрет:** квиз собирается из новых → с
     ошибкой → верных по давности `lastSeen`; `reported` не
     показываются никогда. Квиз собирается всегда; когда новые
     кончились — сообщение «новых вопросов в этой категории не
     осталось, повторяем». `total` с сервера уже есть — подсказку
     можно показать ещё на `/setup`.
   - **Добор вопросов — по провайдеру, не листанием до победного**
     (лимит прокси 30/60 с и лимиты апстримов):
     - QuizAPI — **курсор**: запоминать `offset` для каждой связки
       провайдер + категория + сложность, следующий квиз продолжает с
       него, страница перемешивается на клиенте; при достижении
       `total` — переход в начало, вперёд вопросы с ошибками. Для
       стабильного обхода убрать `random=true`
       (`server/src/quiz/providers/quizapi.provider.ts`).
     - Trivia — `offset` игнорируется, курсор невозможен: запрашивать
       с запасом (`limit` до 50), фильтровать, при нехватке — не более
       одного дозапроса.
     - Mock — тот же курсор, что у QuizAPI (e2e остаются
       детерминированными).
     - Не более 2–3 запросов на квиз; нехватку добирать повторами по
       приоритетам выше.
   - **Фильтрация на клиенте.** Прокси без состояния, аккаунтов нет —
     история только в браузере. Передавать исключения на сервер (POST
     или bloom-фильтр) имеет смысл только с серверным хранилищем.
   - **Ловушка Выживания:** `addQuestionBatch`
     (`src/shared/lib/session-store.ts`) считает пул исчерпанным при
     `added === 0`. С фильтрацией порция может целиком состоять из
     виденных — нужно различать «апстрим пуст» и «всё
     отфильтровано», иначе забег оборвётся ложно.
   - **Хранилище — IndexedDB через `idb`**, только для истории (и,
     позже, тел вопросов для работы над ошибками/офлайна). Почему не
     localStorage: Zustand `persist` синхронно переписывает весь JSON
     на каждое изменение, лимит ~5 МБ, нет индексов; IndexedDB —
     асинхронные записи по одной, индексы по `lastSeen` (вытеснение
     старых) и по `providerId` + `status` (выборка по приоритетам).
     `idb` (~1 КБ) вместо Dexie — запросы простые. Остальные сторы
     (настройки, статистика, XP, достижения) остаются в localStorage:
     они маленькие, а тему `index.html` читает синхронно до первой
     отрисовки. Чтение истории асинхронное — оно происходит при сборке
     квиза, которая и так асинхронная. Запросить
     `navigator.storage.persist()`, чтобы браузер не вытеснил базу.
     Unit-тесты — через `fake-indexeddb` (в jsdom IndexedDB нет).
     Экспорт/импорт (п. 7) должен включать и эту базу.
7. **Экспорт и импорт прогресса.** XP, статистика, достижения и
   настройки живут только в localStorage: очистка данных браузера или
   смена устройства — и всё потеряно. Аккаунтов нет, так что это
   единственная защита прогресса.
   - На `/settings` — «Скачать резервную копию» (JSON
     `quiz-app-backup-YYYY-MM-DD.json`) и «Восстановить из файла».
   - Формат: `{ format: 1, exportedAt, stores: { stats, progress,
     achievements, settings }, history? }` — у каждого стора своя
     `version`. `provider-store` не включать (при mock-сборке
     `providerId` всё равно форсится).
   - Импорт валидирует каждый стор его Zod-схемой и прогоняет
     существующие `migrate`, как при гидрации; битый или чужой файл —
     понятная ошибка, текущие данные не тронуты.
   - Импорт **заменяет** данные (слияние статистики неоднозначно) —
     только после подтверждения.
   - Когда появится история вопросов (п. 6), дампить и IndexedDB.
8. **Мониторинг ошибок и продуктовая аналитика — PostHog.** Сейчас
   ошибка рендера видна пользователю на `ErrorPage`, но не нам; заходов
   и поведения игроков мы не видим вовсе.
   - **Выбор: PostHog одним инструментом** (бесплатно: 1 млн событий
     аналитики + 100 тыс. исключений в месяц, 5 тыс. записей сессий).
     Решающее — кастомные события: бесплатный Vercel Web Analytics
     (Hobby) умеет только просмотры страниц. Запасной вариант —
     Sentry (Developer, 5 тыс. ошибок/мес) + Vercel Web Analytics
     (Hobby, 50 тыс. событий/мес, без кастомных событий). Лимиты
     перепроверить по официальным страницам цен перед подключением.
   - **События:** `quiz_started` / `quiz_finished` (режим, сложность,
     категория, провайдер, досрочный выход), `provider_switched`
     (откуда, куда, причина `kind`), `share_clicked` (п. 1),
     `question_reported` (п. 6). Плюс просмотры страниц.
   - **Сервер — главный источник ценности:** в
     `server/src/quiz/http-error.filter.ts` отправлять каждый
     `UpstreamError` с тегами `kind` и `providerId` (`posthog-node`).
     На Vercel serverless — дождаться отправки до конца функции
     (`flushAt: 1` / `await shutdown()`), иначе события теряются.
   - **Клиент:** `posthog-js`, исключения из `ErrorPage` и
     необработанные ошибки; загрузить source maps, иначе стектрейсы
     минифицированы.
   - **Ключ в браузере — уточнить правило в AGENTS.md.** Сейчас там
     «no API key reaches the browser» и `VITE_USE_MOCK_DATA` как
     единственная клиентская env. Ключ проекта PostHog публичный по
     замыслу (только запись событий, не чтение) — добавить
     `VITE_POSTHOG_KEY` и явно оговорить исключение.
   - **Блокировщики рекламы** режут запросы к posthog.com —
     проксировать через свой домен (`rewrites` в `vercel.json`).
   - **Приватность:** режим без cookie (`persistence: 'memory'`), без
     персональных данных, EU-облако → баннер согласия не нужен.
     Записи сессий — не включать без отдельного решения.
   - **Только прод:** сбор выключен в dev, при `VITE_USE_MOCK_DATA` и в
     e2e/CI, чтобы прогоны не засоряли статистику.
9. **Оба провайдера упали — политика переключений.** Пользователь может
   переключаться туда-сюда сколько угодно: авто-смена на `/setup` ограничена
   одним разом за mount (`switchedFrom` в
   `src/views/setup-screen/hooks/use-provider-fallback.ts`), но ручные
   переключения — из диалога на `/quiz` и из настроек — ничем не ограничены.
   Варианты: помнить, куда уже переключались, и блокировать повторно;
   разрешать только Retry у последнего упавшего провайдера; либо единая

## 2. Зафиксированные отклонения от первоначального плана

Отклонения утверждены пользователем.

### 2.1 Ручная пауза отменена (§6, §10, этап 3)

Изначально план требовал: `Esc` вызывает паузу/выход, пауза таймеров по
команде игрока. **Решение: ручная пауза не реализуется.**

Обоснование: пауза происходит автоматически после ответа на вопрос —
игрок столько времени сколько нужно читает `explanation`, не торопясь
нажимая «Далее»:

- **Блиц** — таймер на вопрос стоит на паузе после ответа и перезапускается
  при переходе к следующему вопросу;
- **На время** — таймер ограничен на всю сессию и продолжает идти,
  это осознанное давление режима;
- **Классика** и **Выживание** — таймеров нет.

`Esc` в состоянии «выбран вариант, ещё не подтверждён» очищает выбор
(см. `use-quiz-keyboard.ts`). Дополнительный экран паузы не нужен.

### 2.2 Звук не реализован (§4)

`features/settings` управляют только темой и анимациями; звуковые эффекты
не входят в объём проекта.

### 2.3 API-ключ убран с клиента (§3)

§3 требовал: «API-ключ хранится в `.env` на клиенте: `VITE_QUIZAPI_KEY`».
**Решение: ключ больше не попадает в браузер и в бандл** — оба live-провайдера
ходят через собственный NestJS-прокси (`server/`), ключ живёт только в env
сервера (`QUIZAPI_KEY`), см. `docs/proxy-server.md`.

Обоснование: прокси снимает ещё и две задачи из §3 — «инкапсулировать доступ
к API в одном модуле, чтобы позже заменить базовый URL на прокси» и
«приводить ответ адаптером к внутренней модели». Теперь единственный модуль
клиента — `shared/api/backend-client.ts`, а адаптация и Zod-валидация
упстримов живут на сервере. Инкапсуляция сохранилась в том же смысле:
базовый URL апстрима не знает ни один компонент приложения.

Клиентский env сократился до одного флага `VITE_USE_MOCK_DATA` (моки —
единственный провайдер, считающий данные в браузере; это сохраняет
герметичность e2e/CI). `.env.example` и `server/.env.example` описывают
обе половины; `.env` и `server/.env` не коммитятся.
