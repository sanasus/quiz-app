# PLAN.md — Quiz-приложение на React (QuizAPI)

Документ — инструкция для кодового агента. Работай строго по этапам, после каждого этапа запускай `typecheck`, `lint`, `test` и делай отдельный коммит.

## 1. Цель

Игровое веб-приложение для прохождения тестов на данных из `docs/api-notes.md`.

Ключевые возможности:
- выбор категории, сложности, количества вопросов и режима;
- режимы: Классика, На время, Блиц, Выживание;
- вопросы с одним и несколькими правильными ответами;
- статистика, достижения, XP и уровни;
- интерфейс на русском и английском (i18n);
- яркий, игровой дизайн с анимациями.

## 2. Стек (решения приняты, не менять без причины)

| Задача | Выбор | Обоснование |
|---|---|---|
| UI | React 19.x (актуальная стабильная версия на момент старта) | Требование |
| Сборка | Vite + TypeScript (`strict: true`) | Быстрый dev, стандарт |
| Роутинг | TanStack Router | Типобезопасные search-params: конфиг теста живёт в URL; loaders |
| Серверное состояние | TanStack Query | Кэш, ретраи, состояния загрузки для QuizAPI |
| Клиентское состояние | Zustand + `persist` | Лёгкий стор для сессии, настроек, статистики, достижений |
| Стили | Tailwind CSS v4 | Токены, быстрая вёрстка |
| Анимации | Motion (бывший Framer Motion) | Переходы, фидбек, конфетти |
| Валидация | Zod | Схемы ответов API и данных из localStorage |
| i18n | i18next + react-i18next | RU/EN, переключатель языка |
| Тесты | Vitest + Testing Library | Логика и компоненты |
| Качество | ESLint, Prettier | |

Перед установкой проверь актуальные версии пакетов и не добавляй зависимости, не указанные здесь, без явной необходимости.

## 3. Работа с API

- API-ключ хранится в `.env` на клиенте: `VITE_QUIZAPI_KEY`. Это осознанное решение (учебный/личный проект). Создай `.env.example`, `.env` добавь в `.gitignore`.
- Доступ к API инкапсулируй в одном модуле (`shared/api/quizapi.ts`), чтобы позже можно было заменить базовый URL на прокси без правок остального кода.
- **Не угадывай формат API.** На этапе 0 изучи актуальную документацию QuizAPI: эндпоинты, параметры (категория, сложность, лимит, теги), структуру ответа, лимиты бесплатного тарифа.
- Ответ API приводится адаптером к внутренней модели:

```ts
type Question = {
  id: string;
  text: string;
  description?: string;
  explanation?: string;
  options: { id: string; text: string }[];
  correctOptionIds: string[];      // 1 элемент = одиночный выбор, >1 = множественный
  multiple: boolean;
  category?: string;
  difficulty: 'easy' | 'medium' | 'hard';
};
```

- Все ответы API валидируются Zod. Невалидные вопросы (нет текста, нет правильного ответа, меньше 2 вариантов) отбрасываются.
- Обработай состояния: загрузка, ошибка сети, 401/403 (неверный ключ), 429 (лимит), пустая выборка.

## 5. Маршруты

| Путь | Назначение |
|---|---|
| `/` | Главная: старт, последние результаты, уровень |
| `/setup` | Выбор категории, сложности, числа вопросов, режима |
| `/quiz` | Прохождение; конфиг берётся из search-params |
| `/results` | Итоги, награды, новые достижения, «повторить ошибки» |
| `/stats` | Статистика |
| `/achievements` | Витрина достижений |
| `/settings` | Язык, тема, анимации |

Защити `/quiz` и `/results`: при отсутствии активной или завершённой сессии редирект на `/setup`.

## 6. Игровая логика

### Сессия (конечный автомат)
`idle → loading → playing → (answered) → finished`

Хранит: список вопросов, индекс текущего, ответы пользователя, время, очки, текущую серию, жизни (для режима «Выживание»).

### Режимы
- **Классика** — без таймера.
- **На время** — общий таймер на всю сессию; по истечении сессия завершается.
- **Блиц** — таймер на каждый вопрос; истечение = неверный ответ, автопереход.
- **Выживание** — 3 жизни, ошибка отнимает жизнь; 0 жизней = конец. Вопросы подгружаются порциями. Настройка количества вопросов для этого режима скрыта и не действует: всегда первые 10 вопросов, далее порции по 10, пока API не кончится.

### Вопросы
- Одиночный выбор: клик по варианту = ответ.
- Множественный выбор: чекбоксы + кнопка «Ответить». Ответ засчитывается только при точном совпадении множества выбранных и правильных вариантов (частичные баллы не начислять).
- После ответа показать правильные варианты и `explanation`, если он есть.

### Очки
Базовые очки зависят от сложности + бонус за скорость + множитель серии (с потолком). Формулу вынеси в чистую функцию с тестами.

### Повтор ошибок
Из экрана результатов можно запустить новую сессию из вопросов, на которые ответили неверно (данные берутся из завершённой сессии, без нового запроса к API).

## 7. Статистика

Хранится в Zustand (`persist` → localStorage) с версионированием и миграцией схемы, данные валидируются Zod при загрузке.

Показывать:
- число сессий, общая точность, средняя серия, лучший результат;
- точность по категориям и сложностям;
- история последних сессий;
- график динамики точности (лёгкий, на SVG/CSS, без тяжёлых библиотек, если не потребуется иное).

Добавь кнопку сброса статистики с подтверждением.

## 8. Достижения и прогресс

- Реестр достижений декларативный: `{ id, icon, titleKey, descriptionKey, check(stats, session) }`.
- Проверка запускается один раз после завершения сессии.
- Примеры: «Первая кровь» (первая сессия), «Серия 10», «Перфекционист» (100% на сложном уровне), «Скоростной» (Блиц без ошибок), «Выживший» (дойти до N вопросов в «Выживании»), «Знаток категории» (50 верных ответов в одной категории), «Постоянство» (игра N дней подряд).
- XP начисляются за сессию, уровни считаются по формуле в чистой функции.
- Разблокировка достижения: тост с анимацией и запись в хранилище (дата получения).

## 9. Дизайн и анимации

- Яркий игровой стиль: насыщенная палитра, крупная типографика, толстые скругления, «объёмные» кнопки с тенью, выразительные иконки/эмодзи.
- Токены цветов, радиусов, теней и отступов вынести в тему Tailwind. Поддержать светлую и тёмную темы.
- Анимации (Motion):
  - переходы между вопросами;
  - фидбек правильно/неправильно (подсветка, «встряска» при ошибке);
  - шкала таймера и пульсация при малом остатке времени;
  - счётчик очков и серии;
  - конфетти на экране результатов при хорошем итоге;
  - появление уведомлений о достижениях.
- Обязательно учитывай `prefers-reduced-motion` и настройку отключения анимаций в `/settings`.
- Mobile-first, адаптив от 360px.

## 10. Доступность

- Полная навигация с клавиатуры: цифры `1–6` выбирают вариант, `Enter` подтверждает, `Esc` очищает текущий выбор (ручная пауза отменена, см. §15).
- Корректные `aria`-атрибуты для вариантов ответа, таймера (`role="timer"`) и тостов (`aria-live`).
- Достаточный контраст, не передавать правильность ответа только цветом (добавить иконки).

## 11. Интернационализация

- Языки: `ru`, `en`; автоопределение по браузеру, переключатель в шапке и в настройках, выбор сохраняется.
- Все строки интерфейса только через ключи i18n, без хардкода в компонентах.
- Тексты вопросов приходят от API на английском и не переводятся; сообщи об этом пользователю в README.
- Форматирование чисел и дат через `Intl`.

## 12. Этапы работы

**Этап 0. Каркас.** Инициализация проекта, конфиги, структура папок, роутер, провайдеры, i18n, тема, `.env.example`. Изучение документации QuizAPI, краткие заметки в `docs/api-notes.md`.

**Этап 1. Слой данных.** API-клиент, схемы Zod, адаптер, хуки Query, обработка ошибок. Тесты адаптера на фикстурах (одиночные и множественные ответы, битые данные).

**Этап 2. Ядро квиза.** Экраны `/setup`, `/quiz`, `/results`, стор сессии, режим «Классика», проверка одиночного и множественного выбора, подсчёт очков.

**Этап 3. Остальные режимы.** Таймеры («На время», «Блиц»), «Выживание», повтор ошибок (ручная пауза отменена — см. §15).

**Этап 4. Мета-слой.** Статистика, достижения, XP и уровни, персистентность с миграциями.

**Этап 5. Дизайн и анимации.** Финальная стилизация, анимации, темы, конфетти, адаптив, доступность.

**Этап 6. Качество.** Покрытие тестами ключевой логики (очки, режимы, достижения, адаптер), error boundary, проверка пустых и ошибочных состояний, README (запуск, переменные окружения, архитектурные решения, ограничения).

## 15. Зафиксированные отклонения от плана

Принятые решения по точкам, где реализация отличается от первоначального
плана. Отклонения утверждены пользователем.

### 15.1 Ручная пауза отменена (§6, §10, этап 3)

Изначально план требовал: `Esc` вызывает паузу/выход, пауза таймеров по
команде игрока. **Решение: ручная пауза не реализуется.**

Обоснование: пауза происходит автоматически после ответа на вопрос —
игрок столько времени сколько нужно читает `explanation`, не торопясь
нажимать «Далее»:

- **Блиц** — таймер на вопрос стоит на паузе после ответа и перезапускается
  при переходе к следующему вопросу;
- **На время** — таймер ограничен на всю сессию и продолжает идти,
  это осознанное давление режима;
- **Классика** и **Выживание** — таймеров нет.

`Esc` в состоянии «выбран вариант, ещё не подтверждён» очищает выбор
(см. `use-quiz-keyboard.ts`). Дополнительный экран паузы не нужен.

### 15.2 Звук не реализован (§4)

`features/settings` управляют только темой и анимациями; звуковые эффекты
не входят в объём проекта.

### 15.3 API-ключ убран с клиента (§3)

§3 требовал: «API-ключ хранится в `.env` на клиенте: `VITE_QUIZAPI_KEY`».
**Решение: ключ больше не попадает в браузер и в бандл** — оба live-провайдера
ходят через собственный NestJS-прокси (`server/`), ключ живёт только в env
сервера (`QUIZAPI_KEY`), см. `docs/api-notes.md` §29.

Обоснование: прокси снимает ещё и две задачи из §3 — «инкапсулировать доступ
к API в одном модуле, чтобы позже заменить базовый URL на прокси» и
«приводить ответ адаптером к внутренней модели». Теперь единственный модуль
клиента — `shared/api/backend-client.ts`, а адаптация и Zod-валидация
упстримов живут на сервере. Инкапсуляция сохранилась в том же смысле:
базовый URL апстрима не знает ни один компонент приложения.

Клиентский env сократился до одного флага `VITE_USE_MOCK_DATA` (моки —
единственный провайдер, считающий данные в браузере; это сохраняет
герметичность e2e/CI). `.env.example` и `server/.env.example` описывают
обе половины; `.env` и `server/.env` не коммитятся.
